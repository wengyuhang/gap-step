## 证据与状态的写法

源码/配置说明实际做了什么；实验产物和对应报告说明在哪个模型、场景和预算下验收；Git 说明何时提交。报告中的实验日期可能早于提交日期，不应混为一谈。提交了代码不等于正式实验已完成，本地生成的结果也不一定随 Git 分发。

当前用户任务决定本次工作范围；不要让历史“主线”或旧待办覆盖当前任务。对有冲突的历史表述，保留来源并在当前状态中解释差异。引用“通过”时写清对象是单测、采样验收、连续域证书还是实机结果。

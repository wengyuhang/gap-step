# 对比实验冻结协议

本目录以后的“正式比较”必须在开始求解前冻结赛道、模型和各算法预算。求解结果只能被记录、重放和审计，不能反向改变同一次比较的输入。

## 一次正式运行的顺序

1. 创建新的、带日期/种子的运行目录；先写入 `scenario/scenario.json`、SC 配置和 SIP 配置。
2. 记录这些文件的 SHA-256，并把哈希、软件版本、随机种子和命令写入 `manifest.json`。
3. 用完全相同的冻结赛道、机体模型、动力学界和原始边界分别运行 SC 与 SIP。
4. 若 SC 使用 SIP 热启动，必须另列为“SC→SIP 修复流程”；主时间比较仍须有两者独立初值的结果。热启动的 SC 时间必须计入端到端时间。
5. 仅记录优化器状态、轨迹、连续域证书和可视化；不得在阅读任何一方结果后改动该运行目录的赛道、窗口运动、裕度、算法目标、迭代上限或初值。

## 修改后的处理

若发现赛道不可通行、参数错误或想测试更难情形，必须新建一个运行标识和新的冻结清单，例如 `track_v6_seed0`；旧运行保持原样并报告其状态。禁止覆盖旧结果或把修改后的续跑当作原运行的“一次求解”。

允许的后处理只有：

- 对保存轨迹进行只读认证、精确碰撞审计和作图；
- 修复报告中的术语错误，并保留原始数值和修改说明；
- 从保存的优化变量继续优化，但必须命名为 `convergence_audit`，不能替换主实验结果。

## 状态语义

- `CERTIFIED_FEASIBLE`：连续时间、所有原始边界和所有动力学硬约束均通过证书。
- `CLEARANCE_VIOLATION_PROVED`：至少一个点违反非零净距；这本身不等价于实体相交。
- `PHYSICAL_INTERSECTION_CONFIRMED`：存在原始边界点严格位于机体长方体内，或等价的零距离实体接触见证。
- `UNRESOLVED`：预算耗尽或数值认证未完成，绝不写成安全。

当前 `wide_scrambled_certified_final` 是赛道设计和 SIP 修复阶段已经发生过的压力案例，不满足本协议所说的冻结一次性基准；它只作为失败模式展示保留。

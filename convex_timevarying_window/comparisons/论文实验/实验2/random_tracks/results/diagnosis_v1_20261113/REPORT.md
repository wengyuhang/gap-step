# 随机赛道、初值和规划算法诊断

本批已按用户要求停止。停止时协调记录93个候选、12/45项最终方法结果，未完成候选的日志保留，不按失败处理。本分析未进行新的优化或实飞。

## 实际版本

本轮使用第一个正式结果已成功复现的冻结Python/CasADi/IPOPT + C++数值核心。轨迹为完整PVAJ七次多项式，时间为累计到达坐标，动力学保持原软罚积分，安全采用补点和完整窗口复查。不是后续原生MINCO版。源和赛道SHA见正式批protocol.json。

## 1. 赛道生成只检查了碰撞空间，没有检查穿越方向拓扑

原TOGT第四、第五窗上下叠放。独立扰动两窗中心后，布局1在第五窗平面法向上的入侧距离为-0.123177m，出侧第六窗为-17.010216m，前后中心位于同侧。相邻弦与第五窗平面几乎平行，法向分量仅为总长度的2.12%。代码route_signs按上一窗中心所在半空间自动推断方向，此时选择了与正常飞向第六窗相反的方向。

布局3同样第五窗前后同侧；布局2的第五窗方向与后续一致，目前已写出的第一个自由/中心候选分别得到16.482692/17.113662秒；自由点外层复查也通过，中心仅完成规划写出，未及外层复查即暂停。布局2第四窗也存在近切向/同侧问题，所以并非宣称该布局整体无问题。

因此，窗口不相撞、直连通道无第三窗干扰，并不足以证明赛道与当前有向穿窗任务相容。本批几何筛查的结论仍成立，不能升级为方向拓扑或动力学可行性结论。

## 2. 有些“未完成”实际来自自动方向约定

布局1低难度两个动态TOGT结果都满足七个实际开口各穿一次、按顺序、完整起终态，且全窗框数值复查clear。原task_invalid来自第五窗的forward=false。若任务只要求按序各穿一次，这两条应判无碰撞完成；若要求固定方向，应在生成赛道时明确固定法向并让所有方法一致使用。原表保留，不覆盖；本诊断明确标注此口径问题。

## 3. 初值并非八条已经基本可行的轨迹

第一套布局三个难度共24条初值，第五窗沿代码指定方向的速度全部为负，范围-9.8813至-1.3721m/s，而有限问题要求至少+0.1m/s。这条0.1m/s限制来自冻结历史代码，不是本次新加入。中心位置、Sobol时间和位置型MINCO虽然一致，但没有先保证有向穿窗任务。

低难度8条初始动力学罚项范围约9601至3.63e8，而飞行时间仅约16至26秒。直接进入时间加软罚目标，意味着优化器首先面对尺度很大的动力学修复。反例是中难度seed4：轨迹23.537262秒、动力学罚项为0，第五窗沿指定方向速度-4.090378m/s，有限约束最小值-4.190378。说明不能把所有失败都归咎于动力学或初始时间过短。

当前原soft_dynamics.solve_all将原最小二乘可行性恢复替换为恒等返回，冷初值直接送入IPOPT。八初值增加了时间相位分支，没有修复共同的方向错误。

## 4. 复查和补点之间有机制缺口

对低难度中心seed7重建已收敛的最终曲线，第五窗在11.015103、11.442920、11.483483秒三次穿越开口。中间指定节点的法向速度为+0.100000m/s，恰好压在旧方向约束边界，前后两次速度分别为-0.855399和-0.109847m/s。

safety.passage发现段内部额外过窗即返回repeat_aperture_crossing，但witness_u=None。外层只对有witness_u的碰撞证据补安全距离约束；因此重复穿窗不会形成新的有限约束，最后added=false就直接退出。

这次已写出候选中17个最终失败候选仅剩这种重复穿窗且没有可补点。低难度7个中心初值均全部有限问题Solve_Succeeded，最后停在同一重复穿窗解附近17.651秒。由此可知，“再增加IPOPT迭代”不会修复这一层问题。安全距离约束也不能自动表达“只穿一次”。

## 5. 数值求解仍有第二类独立问题

已保存本文候选的222次有限IPOPT调用中，193次Solve_Succeeded、27次Maximum_Iterations_Exceeded、1次Solved_To_Acceptable_Level、1次Infeasible_Problem_Detected。少数第一轮即失败，另一些经过多轮收敛补点后才达到上限，必须分开分析。

每次有限问题不仅有71/96个轨迹变量，还含1584个动力学软罚辅助变量，约1655/1680个总变量以及两千余约束。全PVAJ、到达相位、选点和软罚辅助量耦合，且采用L-BFGS近似Hessian。初始巨大罚项与方向冲突是已证实的困难来源；尚不能据现有日志断言全部27次上限都由同一个数值原因造成。

## 建议的处理顺序

1. 先统一任务方向。若指定方向，保存显式的每窗有向法向，不再由几乎共面的前一中心取sign；叠窗作为一个组合保持其进出拓扑，再做共同随机扰动。若方向不限，应去掉人为方向失败口径，并相应处理优化中的固定方向限制。此项需保持五方法任务完全一致。
2. 生成器加入方向与进出几何检查，而不是用某方法是否跑通筛赛道。保留本次负结果，任何新生成规则使用新版本编号。
3. 同一初值先做同约束下的可行性恢复，再最小化原竞速目标。中心点仍可作为位置初值，段时间和PVAJ应联合恢复；不能只增加随机时间数量，也不必额外添加竞速代价补丁。
4. 区分安全分离oracle与穿越任务oracle。重复/反向事件要提供对应的任务修复机制或明确停止原因，不能当成距离补点已处理。当前None导致的静默死路应消除。
5. 修复前四项后，先用一个静态、一个低动态、一个高动态任务，各跑同样8初值，记录8/8合格率、各自完整时间、相对最好解差距、每轮KKT残差和耗时。只有稳定后再恢复九赛道矩阵。不会用其他方法最优解冒充独立冷初值，也不会把“一个初值成功”写成“全部稳健”。

“全部初值找到合格优秀的解”应分为8/8安全任务可行，以及8条竞速时间接近两个验收项。当前首先受任务方向与补点机制缺口影响，单纯扩大多初值或迭代预算不合适。尚未证明修正后8/8必然达成；本报告为定位和改进方案，不是新算法的完成声明。

## 改动与证据

1. 保留前序验证的等价稀疏表达、精确Hessian、theta_max_fact=1和关闭watchdog；续求五个push/fraction=1e-9，避免内部热启动把原好点推离边界。
2. 原曲率八初值先用未优化MINCO生成时间和VAJ，必要时1.25倍退让，每次重算真实移动中心。新增固定8步括区细化，保持已验证的可行端点。只检查原17节点动力学，不声称初始连续安全或全局最短初始化。自由点初始始终在中心。
3. 同样数值设置下，未细化中心seed2/4首轮5000失败；细化后分别3787/3718次严格收敛，最终10/13轮全部成功。其余改变的初值随后完整验证通过，未拼接不同规则的成功候选。
4. 外层预算从硬编码24改为可配置；新入口统一64。freq4原24轮均严格收敛但未完成复查，原初值重跑前24轮保持一致，第35轮安全复查通过，耗时1385.45s。没有允许失败有限问题继续补点。
5. 原模型目标/系数/导数审计通过；一项有限差分需要更小步长才能进入收敛区，原未通过记录保留。10项CTest通过。monotone对照四项失败，未采纳。

计算仍是分钟量级，尚未解决求解速度问题。自由点21窗中19窗点域利用率超过95%，平均偏离中心0.616m；相比中心路程342.221/347.213m，表明已利用开口，但不能由集合包含关系推出必然大幅提速。

## 可复现C++入口

```bash
curvature_initials INPUT_ROOT airsim_freq3 NEW_INPUTS --robust-ipopt-profile
native_sip_matrix NEW_INPUTS INPUT_ROOT/assets/airsim_freq3/scene.json NEW_RESULTS SIP_BINARY MESH_BINARY
```

第二条运行两方法八初值，共16候选。第一条已将数值设置和64轮预算写入输入，不需要手工修改JSON。FINAL_PROFILE_EQUIVALENCE.json确认新入口与本次验证原始曲线和求解设置相同，仅外层上限统一64。模型与初始化均C++。

# 当前IPOPT与SLSQP同步记录（2026-11-17）

以`cpp_runtime`当前原生软动力学规划定义为准。历史`IPOPT的c++实现（原生minco版）`和`SLSQP的c++实现`是归档，未将其旧赛道、硬动力学、x500或时间/工作空间限制复制进来。最近SLSQP试验原本就使用当前`src/sip_planner.cpp`，不是旧包的`hard_problem.hpp`；本次修正接入缺口，并增加可运行的一致性验证。

## 同步后的结构

`include/finite_nlp.hpp`保存统一有限问题(x,p,f,g,lbg,ubg)，两端使用同一PVAJ MINCO、运动函数、物理量恢复、目标、约束和导数。IPOPT直接接收该问题；SLSQP只把相同有界约束转换成“等式在前、其余≥0”的接口。原变量上下界和初值在求解分支前统一生成。以后修改规划模型只修改共享构造，不维护两份物理定义。

|内容|当前共同定义|
|---|---|
|轨迹|实际完整PVAJ MincoPV，derivative_order=3；不采用基线轨迹加偏移|
|时间|各段独立TOGT正映射；当前原生分支无段时间范围或工作空间限制|
|选点|自由点为内缩开口平面内显式xy，四边形半空间/圆盘与相应变量界；中心版无选点变量|
|窗口运动|累计到达时刻进入解析运动函数，不冻结运动中心|
|动力学|从轨迹导数恢复两项角速度及四电机推力；当前软罚，非旧SLSQP硬采样约束|
|目标|时间加动力学软罚，权重1/1000；保留0.01平滑核，不新加倾角或snap目标|
|积分|当前共同固定16区间/17节点；不是原作者自适应8～32区间的完全复刻|
|参数|读取同一manifest/车辆/动力学文件；本测试为QuadA、约0.20m安全球和0.15m物理球，未换回旧x500|
|基础约束|保留当前已有0.1m/s法向速度条件，两端相同；本次未新加|
|安全补点|同一有限可行性门槛和复查器，每窗每轮最多一个最坏witness，新增有限问题用本方法上轮变量|
|初始化|同一未经优化原始时间/VAJ、位置在中心；没有跨方法优化解初始化|

两端支持同一`direct`表达式，亦支持同一`residual_epigraph`表达式。比较两求解器时必须同时选择相同表达式；不能默认把直接式和辅助变量式的变量维度、收敛耗时视为同一有限NLP。求解器原生停止标准和对偶热启动能力仍不同，不把成功标签混同为相同KKT精度。

## 修复的具体缺口

1. SLSQP原先只接入直接软目标，现在也可接当前辅助变量软目标；不引入旧硬动力学问题。
2. 新输入的旧辅助变量数组可为空，原实现会读空数组。现在依据当前六项残差尺度生成17节点辅助量尺度。
3. 有限约束界按当前基础行和实际辅助行显式构造，不靠旧32区间数组盲目resize。
4. 结果动力学说明由旧“33节点”改为实际17节点，并记录实际表达式、区间数与共享问题版本。
5. 未知后端/软罚表达式直接报错，不静默回落到另一种求解器或表达式。
6. 将原样Kraft内核和许可独立放入`cpp_runtime/vendor/slsqp`。当前构建不再依赖旧SLSQP规划目录，源码SHA与旧内核一致。

上轮可选数值预调理/单位实验开关仍保留；本次一致性核对均关闭，未把实验性改动悄悄设成正式默认。

## 验证结果

- `results/finite_model_parity_v2/SUMMARY.json`：8组两端模型对照，每组三个求值点，包含真实运动函数与模拟补点后的几何行。直接式覆盖Split-S7/AlphaPilot11/AirSim21自由与中心，辅助变量式覆盖七窗自由与中心。目标、梯度、约束、雅可比、变量界、初始曲线和参数差值全部0。该模式不执行优化，`found=false`，不能作为安全或完赛结果。
- 新有限NLP单测实际调用IPOPT/SLSQP求同一含等式、单边/双边约束与变量界的问题，并核对SLSQP约束及Jacobian转换、整体目标单位。
- 8项CTest全部通过。
- 两条正常SLSQP规划回归与原批逐值一致：自由点7.192353372597216秒，中心6.675988433393119秒；完整系数、时长、变量、穿越点/时刻、目标及原始初值均一致。原几何复查通过。

本次解决的是版本与模型接入一致性，没有宣称已修复此前自由点独立局部求解偏慢的问题。没有重跑完整竞速矩阵或Gazebo，历史结果均保留。

## 可复跑命令

```sh
ctest --test-dir /tmp/equilibrated_native_slsqp_20261116 --output-on-failure
# 每次使用全新输出目录；三个输入参数分别是当前可执行文件、共同原始输入根、场景根。
/tmp/equilibrated_native_slsqp_20261116/finite_backend_parity SIP CURRENT_INPUTS CURRENT_ASSETS NEW_OUTPUT
```

单个原生软问题在`manifest.json`指定`native_finite_solver: ipopt`或`slsqp`即可切换，`native_soft_formulation`单独固定为`direct`或`residual_epigraph`，其他输入不变。正式入口仍为`--soft-mincopv SCENE 1000`。

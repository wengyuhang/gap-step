# 动态CPC C++：22条件固定协议（2026-11-17）

作者代码：复现/cpc_dynamic/vendor/rpg_time_optimal，提交f5541b6d9d3dee563e01a64ec1994b8ed6c0076c，GPL-3.0。C++实现按src/planner.py、quad.py、integrator.py方程迁移；保留原单初值折线/进度初始化、vel_guess=3、总时间目标、进度/顺序、0.3m邻域、0–0.01互补放宽、IPOPT默认设置及10000迭代上限，不增加安全过滤/补点/多初值。

所有条件400均匀优化区间，每区间四个原RK4积分小步、同一个电机输入，沿此前400区间协议。不要求dt<0.03s。起终位置及零速度/角速度、水平yaw0和起终悬停输入与当前任务匹配；它们是明确的任务边界适配。节点高度界0.5–100m和总时间0.1–150s沿作者实现。四元数按作者不显式归一化，记录范数误差及独立加密积分漂移。

使用robust_ipopt_full_20261117/source_inputs同22个scene/vehicle。质量0.85kg及惯量、完整物理混控矩阵来自QuadA；每电机0.1–6.879N，角速度xy15/z2.99rad/s，零名义阻力。物理电机顺序到作者顺序映射[1,3,2,0]；模型测试对照作者四元数乘法与混控通过。CPC完整状态/电机节点硬界与其他方法软动力学不同，不能称同可行域消融。

动态适配仅把节点航点替换为已知运动c_j((k+1)T/N)，其导数随总时间自动传播。每窗已知平移/摆动及运动方向保持。第七导航点保持0.3m邻域语义，不变成实体门。最终到达原任务终点，不能只统计末窗时间。

静态先启动单次正式400节点求解，后续21条件最多7个进程，BLAS/OMP=1，不重复静态。各场景一次求解，不使用其他方法或其他场景的优化解。后续不因成绩改变协议。有限约束残差<=1e-5的有限候选可记录为数值可行，优化器是否成功另列；不把未收敛直接写成已收敛。

碰撞检查沿历史CPC原生RK4参考，每≤1ms采样、真实三角网格和0.15m球，有限开口过平面事件做括区间求根。单独记录积分缺陷、四倍加密累积漂移、最近中心距离、门序、终点。采样无碰撞不升级为连续安全证书；与多项式方法的浮点包络复查证据等级在最终表注说明。碰撞不修改/替换轨迹。仅规划，无Gazebo。

计算时间按各条件setup+一次solve墙钟报告，setup包括建图/创建求解器；几何复查另列。本文是八配置并行到最终选择的墙钟，TOGT是独立单次建模/求解，Wang是拼接全赛道局部规划墙钟（不含此前离线建图）；这些计算口径逐列写明，不累加并行候选CPU耗时。

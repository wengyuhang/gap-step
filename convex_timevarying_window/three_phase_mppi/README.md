# Three-phase dynamic-gate MPPI

2026-09-23：独立实现用户确认的三阶段机制；不是旧 V3 的改名或参数变体。

## 机制与边界

1. TRANSIT：GPU MPPI 跟踪当前动态三窗 TOGT。无参考时仅执行已检查的初始化保持动作。
2. PREPARE：预计进入机身接触区前主动接管，不等待碰撞预警。采样移动窗口的未来出口时刻、
   面内位置和出口速度，用当前 PVA 到出口 PVA 的五次多项式参数化反馈策略。
   目标主要为整机清出时间；参考点仅提供部分采样中心，不要求贴着不安全参考飞行。
3. CROSS：机身接触窗口厚度区后继续自主控制，首要目标完整顺向清出。
   禁止退回入口侧，中心越面后禁止反向越面；完全清出才更新实际门序。

窗口位姿按每个预测时刻查询，包括其平移与三轴旋转；所有实际门框仍参与局部碰撞筛选，
不把“门间绝对无碰撞”当作删除其他门框的理由。不检查完整赛道轨迹。
PREPARE 接管根据局部前向预测入窗时间与朝向窗口的接近速度，不把100 ms计算预算当接管距离。
阶段按实际状态维护，PREPARE 在当前门清出前锁定，避免模式抖动。

GPU 在低维反馈策略参数空间进行 MPPI 重要性加权，而不是逐个电机时序噪声；
所有候选经 x500 17维内环近似模型展开。加权策略重新检查，失败则选原始合格样本。
保留上一条策略作为候选并从当前状态重算，不设旧版绝对穿窗期限、固定反馈误差域、
禁止门内重规划或退回入口候选。无合格候选明确记录为预算内未找到控制，不能证明赛道不可行。

重规划只有三类事件：实际整机过门、TRANSIT跟踪偏差过大、TRANSIT遇险临时避让后恢复。
PREPARE/CROSS本身不触发重规划；当前反馈动作未来100 ms安全才启动。
新参考来自当前实测 P/V 和模型 A/J；任何阶段可计算，参考替换不打断 CROSS。
初始化、候选筛选、加权复核和 CPU/GPU 传输都计入在线时间；CUDA编译预热单列。

## 复用范围

只复用赛道查询、TOGT参考求解器、x500物理积分/底层反馈函数和PX4通信会话。
`engine.py`只提取旧native源中的物理/几何/反馈函数，**不包含**旧 v3_rollout、
guided、controller、scheduler、passage_contract 或恢复状态机。新状态机/代价/采样独立。
经验内环模型、0.35 m定位/跟踪余量不是已证明鲁棒界；之前PX4绝对定位误差曾超过此值。
名义模型实验、真实PX4闭环、密集审计和连续安全证明必须分开。

完整机制、用户假设与实现补充见 [DESIGN.md](DESIGN.md)，实验协议见 [PROTOCOL.md](PROTOCOL.md)。
本文件的算法说明不表示已经验收成功。

2026-09-23最终冻结验证：22项测试通过；四组名义模型与四组PX4均未完成七窗返航。
PX4分别完成4/2/4/3窗，2677个MPPI周期最大49.448 ms，107次TOGT最大78.495 ms。
计时达标不等于安全竞速目标达成。逐条件负结果与失败解释见 [RESULTS.md](RESULTS.md)。

## 当前实现细节

- 九维采样：出口时间、二维面内位置、法向出口速度、二维切向出口速度、三个初始期望加速度修正。16384个GPU候选，
  一半广域探索，一半围绕上次出口方案细化；保留原方案作为独立候选，全部从当前状态重算。
- 位置五次多项式只参数化反馈目标，不把它当作真实飞行轨迹；实际预测包含17维CTBR模型、
  内环近似、电机滞后、阻力、5 ms RK4和10 ms反馈/运动门几何。
- TRANSIT预测0.8秒。自主阶段按距离、径向/横向速度估计局部所需时长，限制为1.5–6秒，
  完整退出后再检查1秒交接段即停止；不是整赛道检查，也不是必须等待1秒才重规划。
- 跟踪误差触发：位置0.5 m或速度2 m/s。100 ms检查使用当前动作而非新TOGT轨迹。
- 新候选在原0.35 m误差裕量上另预留逐渐增大的反馈空间（前0.3秒从0增至0.12 m）；
  不因实际初态已经在额外缩紧区之外而拒绝所有恢复候选。实际执行/100 ms准入仍使用原界。
  反馈期望加速度限6.5 m/s²、期望倾角38°，保留纠偏能力；物理拒绝界仍为8 m/s²/42°/12 m/s。
  输出还包括11.5 m/s反馈速度调节、当前姿态下总推力区间投影和角速度阻尼；
  有限房间采用统一末端转向/制动距离代理。这些是经验近似，不是鲁棒安全证书。
- 没有“所有采样失败就证明赛道不可行”的分支。失去候选且原动作不再覆盖安全前缀，记控制失败。
- 过窗时保留可执行出窗策略作为TRANSIT候选，按新的实际门序检查，不直接丢弃；
  GPU无合格更新时可用CPU双精度重新检查旧策略，但批量采样仍在GPU。
- 无剩余窗口时，新reference.py用同一TOGT动力学目标优化三段自由空间返航曲线，
  保留当前PVAJ边界；不使用旧模块的单段估时捷径，不对新路径做安全准入。
- PX4入口采用既有论文对比的参数（特别是SENS_GPS0/1_DELAY=0）；首轮旧入口默认110 ms
  导致定位假设失效的运行保留，不作为同设置成绩。未关闭传感器检查或修改门运动。

运行（仓库根目录，wyh环境）：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m pytest -q convex_timevarying_window/three_phase_mppi/tests
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m convex_timevarying_window.three_phase_mppi.experiment --outdir NEW_DIRECTORY
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m convex_timevarying_window.three_phase_mppi.px4 --outdir NEW_DIRECTORY
python -m convex_timevarying_window.three_phase_mppi.report RUN_DIRECTORY
```

`px4`会重启专用实验容器，不影响replay容器。结果必须写新目录。

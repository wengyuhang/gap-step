# TOGT-MINCO v3：PX4/Gazebo 两条件对比

日期：2026-10-07。结论：两个预先指定条件都通过当前主验收，但都慢于原优化 MPC 和 Wang 独立复现。
这次完成的是替换轨迹表示后的闭环试测，不是证明 MINCO 更慢，也不是全矩阵竞速优势。

## 方法与可比范围

新代码在 `convex_timevarying_window/togt_minco_mpc/`，不覆盖旧方法。
原规划是每个飞行区间单段五次 Hermite；新方法采用 TOGT MincoSnap 对应的 MINCO-s4
七次多项式线性系统：全局耦合系数、内部 C6、起终点 PVAJ，每个飞行区间两段，增加自由三维
中间位置、各段独立时长，动态开口内穿越点仍可优化。执行 IPC 与采样使用全部八个系数，
没有压回五次参考。测试对照了仓库 TOGT MincoSnap 线性系统。

这是 CasADi 实现 MINCO 数学系统的组合方法，不是直接调用发布版 C++ TOGT 优化器。
继续使用两未来窗加停留终点、原动态七窗场景、x500/PX4、同一 condensed MPC、0.2 s 重规划和
150 ms 物理时钟参考接续。原时间加 jerk 积分、安全软目标、几何/动力学采样准入保留；
新增头部 jerk 接续和末端零 jerk 条件。并不能称“除曲线外一切数学条件严格相同”。

v3 用 L-BFGS-B 和标量 MINCO 梯度代替 v1/v2 的 IPOPT 全约束 Jacobian，
固定归一化违反量三次罚权 1e5，内部墙钟预算 55 ms，为采样检查和 IPC 留出余量。
搜索罚函数不保证安全：执行仍须原约束残差 <0.003、完整局部 10 ms 采样检查通过，
规划净空要求 0.35 m、软偏好 0.50 m。完整在线调用超过 100 ms 即失败。
最终没有启用 JIT；起飞前构图约 3.90/3.96 s，不混入飞行时间或在线周期。

因此本批可以回答“这个在线 MINCO 组合能否飞、有没有实际提速”，不能单独识别
曲线表示、终端 jerk 条件、搜索算法或罚权对时间的因果贡献；也不声称其可行轨迹集合严格包含 Wang。

协议和源码：[protocol.json](protocol.json)、[source_snapshot](source_snapshot/)。
完整数字：[summary.json](summary.json)。每条件一次、无重试，两趟源代码相同。
每个子目录保存 result、execution、ULog、遥测、规划/MPC 调用记录和安全审计。

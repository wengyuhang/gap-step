# 2026-09-23：前三项决策问题的修订与闭环验收

本轮按用户授权直接修改，不调用技能，不改两论文基线、七窗运动、机体尺寸、PX4参数或物理上限。
**代码修订不等于全赛道问题已解决。以下开发运行均独立保留，不合并成同版本成功率。**

## 1. 暂时安全不再等同于有效恢复

自主候选分成完整穿窗与入口恢复两类。存在合格完整穿窗候选时，不允许加权或重新筛选退化成不穿窗。
没有完整穿窗候选时，新恢复候选必须改善入口状态指标；仅仅不碰撞、不越界不再足以替换旧方案。
指标同时考虑入口侧距离、横向对准距离、横向相对速度和反向速度。初末状态使用同一个未来窗口姿态，
避免窗口自己移动制造进度。完整穿窗候选按退出时间和后续窗口入口调整代价比较，不能只贪快退出。

该指标是具有时间量纲的运动学启发式，不是可达集证明。滚动优化的预测末端改善也不等于实际进度必然单调。
没有改进候选时只保留仍通过检查的旧动作，或明确记录 `no_admissible_update`，不称安全恢复完成。

## 2. 单独保留当前窗口的穿越方案

`passage` 与普通执行 `maneuver` 分开保存。普通跟踪更新不能把已存在的穿窗方案从记忆中覆盖掉。
每轮从实际/接入预测完整状态重新验证反馈执行；有效时保留旧方案，并约束新方案不得推迟原来的绝对穿窗目标。
扰动导致旧方案安全但晚于目标时，可以保留它，但明确记录 `passage_timing_slip`，不把目标悄悄向后移动。
旧方案失去适用域或硬约束不通过时不强行执行，仍不具备递归可行性保证。

候选的最大搜索视界仍为2.5秒。发现完整退出后，检查到退出后约300 ms：覆盖一次100 ms计算、
80 ms接入前瞻与100 ms执行复核并作时间网格取整。这里是已验证的后续动作，不是新增300 ms等待重规划条件。
保留全部门框、工作区、动力学、任务及末端制动代理检查；事件终点之后的数组填充值仅用于批量布局，
不参与代价、不导出为可执行控制。没有完整穿窗的候选仍检查完整局部视界。

第一版仅保留约120 ms后续，PX4 _02暴露出交接不足，已修正；同时修正真实门序递增后误跳过旧安全尾段的问题。

## 3. 远期问题请求重规划，近端风险才触发自主模式

- 原参考较远处风险、跟踪候选完整视界不合格：请求TOGT，不再仅因此去掉参考跟踪代价。
- 由实际接入状态生成的跟踪控制，未来100 ms物理/任务检查失败：自主模式。
- 即将进入窗口、却没有完整穿出的跟踪候选：按当前速度对应的调整时间提前自主准备，不能机械等到100 ms。
- 已在窗内：保持当前窗口任务；中心过面与整机清空分开，清空前不提前追下一门。

近端检查仍不是执行授权：所有替换动作必须通过其完整局部合同检查。100 ms计算允许条件未增加等待余量。
捕获时间采用速度/加速度代理且上限1秒，仍是经验规则，不是完整可控性证明。

## 配套一致性与计算修正

1. _02/_03续接拒绝大量含64位：反馈修正后的角速度命令未遵守采样器已有的8 rad/s²变化率限制。
   现实际发送、短段预测、旧方案复核使用相同限幅；没有删除该检查或放宽物理上限。
2. 单条保留方案的反馈复核改为原生FP64计算，完整保留误差域、反馈公式和限幅。
   与Python逐步实现逐控制量一致性测试通过；16384候选采样及批量预测仍在GPU，不是改回CPU MPPI。
3. TOGT请求中的模型A/J使用实际最近发送的指令，而不是未限幅的反馈值。
4. _05在接近房间y上边界时触发区间检查。旧边界距离用总速度估算逼近速度，把沿墙面的速度也计入。
   CTBR现按每个边界法向速度加同一物理加速度界计算区间余量，工作区和0.35 m误差余量不变。
   门框的三维运动界不变；旧电机路径默认不启用此选项。这是方向相关的更紧上界，不是省略区间检查。

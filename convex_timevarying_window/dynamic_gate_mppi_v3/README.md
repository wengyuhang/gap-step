## 已实现

- `reference.py`：当前 PVAJ 起点、动态三门联合穿越点/时刻 TOGT；最后三门包含真实返航终点。
  复用原 MINCO 和 `_minimize_togt_lbfgs`；增加 x500 自由终端梯度绑定，不修改旧 native 库。
  优化在预算的75%处结束，保留已找到的参考候选，预留构造/传输时间；不宣称收敛，不检查整圈安全。
  单独进程计算，超时结束该任务并重新准备工作进程。新参考不能直接执行。
- `rollout.py` / `native/rollout.cpp`：x500 的17维状态（位置、速度、四元数、角速度、四电机转速），
  四旋翼目标推力输入，真实混控参数，电机转速上升/下降滞后和面内阻力；RK4 5 ms。
- `geometry.py`：共享三维窗口查询，精确圆框/多边形胶囊轴线距离，全部七门和原工作区。
  10 ms区间补偿包含整个区间的无人机速度界和门框平移/旋转速度界。
- `controller.py` / `gpu.py`：默认GPU 16384候选（旧CPU冻结版512）、在线2.5秒视界、20 ms控制网格、两组平滑噪声和机动偏置；
  硬筛后计算竞速/参考/平滑代价；加权结果重新预测检查，否则选安全原样本；控制缓存有截止时刻。
  数值诊断支持初始TOGT推力采样种子，仍受同一筛选，不作为可执行授权。
  本轮PX4入口先建立已检查的执行缓存，因此采样实际优先沿用缓存，而非初始TOGT种子。
- `scheduler.py`：风险/过门/跟踪偏差产生请求；当前执行片段未来100 ms不危险且非正在穿门时启动，
  单进程忙时合并请求。结果核对截止时间、实际门序与当前时刻接入偏差。
- 候选和实际状态各自维护门序；完整机身出门才计数；门移动不能凭空产生进度奖励。

## 与文档及旧场景的关系

用户已同意保留旧赛道完整三维平移/RPY运动，而不是PDF中的固定平面运动；
正式PX4协议把初始等待计入比赛时间。数值开发入口不满足正式时序，不能拿它的模型时间比较圈速。
默认误差裕量0.35 m，尚未证明覆盖 PX4 跟踪、定位与数值误差；不是整圈连续安全证书。
模型的动力学限制按5 ms采样筛选；不能升级为连续动力学认证。
PDF未规定的 MPPI 温度默认1，推力变化率80 N/s，总推力机动偏置±3 N、滚转/俯仰力矩偏置±0.05 Nm。
温度0.1仅为开发敏感性试验；未据评估相位逐门选参数。

`diagnostic.py` 的模型在计算后逐拍积分，**不是独立真实物理仿真，也不模拟控制延迟**。
`--paced` 只防止模型时钟跑得比异步工作进程更快，不消除计算超期，更不等于实时闭环。
记录所有20/100 ms超期、失配结果、片段耗尽及超时，不自动保持最后输入续飞。

## 运行

在仓库根目录、conda `wyh`：

```bash
OPENBLAS_NUM_THREADS=1 python -m pytest -q convex_timevarying_window/dynamic_gate_mppi_v3/tests
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m convex_timevarying_window.dynamic_gate_mppi_v3.diagnostic \
  --outdir convex_timevarying_window/dynamic_gate_mppi_v3/results/new_development --duration 60 --paced
python -m convex_timevarying_window.dynamic_gate_mppi_v3.report \
  convex_timevarying_window/dynamic_gate_mppi_v3/results/new_development
```

输出目录必须是新目录；源码快照从 `_04` 起在运行开始时保存。之前记录为开发期结果，
尤其 `_03` 运行期间源文件有后续修改，结束时hash不是其准确执行快照，不能作为冻结实验。
原结果保留，不用重跑覆盖。

现有容器为 PX4 1.18 开发版，git `83c4f4e580558816f0e398918f66358988004696`。
其 [MAVLink接收源码](https://raw.githubusercontent.com/PX4/PX4-Autopilot/83c4f4e580558816f0e398918f66358988004696/src/modules/mavlink/mavlink_receiver.cpp)
没有 `SET_ACTUATOR_CONTROL_TARGET` 接收分支；旧 CTBR 接口不能冒充四电机推力接口。
PX4 [Offboard文档](https://docs.px4.io/main/en/flight_modes/offboard)提供 ROS 2 `ActuatorMotors` 直控路线。
首次准备时没有 ROS 2/Agent且Docker连接失效代理 `127.0.0.1:10808` 被拒绝。
后查到本机7890可用，使用任务临时loopback转发下载依赖，下载后已关闭；没有改Docker全局配置。
`ros_ws`仅生成与实装PX4兼容的两个消息，`ros_motor_bridge.py`经ROS 2传输目标电机输入。
跨容器DDS初始共享内存通信不通，改用host网络/IPC、UDPv4；原Gazebo和PX4镜像不变。
`px4_interface_probe_20260919_03`证实切换后电机输出误差小于4.2e-5 rad/s，
ULog确认角速度控制及分配关闭；模式切换约0.5秒，正式适配在原30秒准备阶段第29秒开始交接。
`THR_MDL_FAC=0`及150/1000 rad/s原输出范围不变，模型和输入下限对齐150 rad/s。
没有用Gazebo电机话题绕过PX4；比赛中不走旧CTBR投影或位置控制器。

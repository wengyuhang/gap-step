# 穿窗任务一致的 GPU MPPI（2026-09-20 开发修订）

目标仍是动态三窗TOGT + GPU MPPI，不增加逐门专用路径。正常为参考跟踪，危险为完全不读取旧TOGT的自主控制。
本页记录本轮设计和证据边界；开发中成功与失败均保留，不能将一次成功或零碰撞写成鲁棒保证。

## 控制规则

1. 实际整机出门、跟踪偏差或风险产生TOGT请求。当前执行方案未来100 ms无危险且不在门内，即可从实际P/V、模型估计A/J启动。
2. 正常模式跟踪位置和速度，分别按0.5 m、2 m/s归一化；参考时间表不修改实际门序，也不屏蔽跟踪代价。
3. 危险模式采样当前门的完整出口点、出口速度和到达时间，生成局部五次曲线的反馈控制提案；不读取危险参考。
   出口横向偏移为统一的±0.25/0 m网格，速度2/4/6/8/10 m/s，四档统一时长倍率；另外采样朝下一门的切向出口速度。
   到达时间依据完整出口距离、当前速度和加速度尺度，不仅依据到中心的距离。
4. 提案在实际完整出门后朝下一门/终点转向，使当前穿越和后续飞行在同一个预测中评价。
5. 上一拍移位方案与新提案同时硬筛、评分，选取采样中心，再生成16384条GPU候选。
   不能每拍强制以新平滑曲线取代已选方案：已实测旧写法360条新提案的首拍相对悬停最大变化仅8.88e-16 N。
   现加入20 ms控制前瞻，让新提案首拍实际响应；已选的未来机动不被无条件重置。
6. MPPI加权结果重新做FP64预测筛选，并与最佳合格原样本比较；较差或不合格时保留原样本。
   这是带单调接受检查的采样控制，不宣称原始MPPI理论的无偏最优解。
7. 条件式穿越期限：从当前实测状态重新验证缓存剩余控制。只有整段仍安全且预测完整出门时，
   新方案才不得晚于该方案的出门时刻；没有合格替代则继续该缓存。缓存失效立即解除期限，安全优先。
   这防止滚动优化不断把未来穿越后移，不是强制执行已危险的旧方案。
8. 候选反馈补偿预测模型已有的旋翼阻力和陀螺项，姿态阻尼按惯量设置；目标倾角留5%动态响应余量。
   这是通用模型一致控制，不是逐门调参；实际加速度、倾角和电机限制仍重新硬筛。

## 可行性约束与局限

- 全部窗口仍按有限门框检查碰撞，不增加实体无限墙。
- 对当前未完成门增加入口侧有向任务约束，禁止从孔外绕到背面当成进展；已完成门和未来门不变成无限墙。
  这是保守的控制可行域限制，可能排除某些先远处跨平面再折返的物理可行路径，不是无损全局拓扑表示。
- 入窗须有完整向前出门见证；已在门内则优先完整前出，否则只允许已检查的退回，不计完成。
- 参考预测若在整机完整退出前反向退回，即使未碰框，也属于任务风险；不能跟踪名义点的“碰到窗口再返回”来伪计整机穿越。
- 未完成穿越的候选末端保留法向制动距离：v_close²/(2·0.65·a_max)+0.15·v_close。
  这是模型下可恢复性的保守启发式，不是已证明的四旋翼控制不变集；不能称递归安全证明。
  工作区六个边界也检查末端相同制动距离，避免短视界后在边界无法制动。
- 在线入口默认2.5秒局部预测（约覆盖12 m/s、0.65·8 m/s²和0.15秒响应尺度），不是全赛道安全检查。
  旧1秒配置仍可显式使用，CPU参考/旧测试保留该默认配置。几何/动力学时间网格仍10/5 ms。
- GPU FP32筛选后，最终控制经CPU FP64复核；0.35 m模型误差裕量未被削弱，也尚未获PX4误差上界证明。

## 计算与记录

MINCO只在本方法内将已求解的多项式向量化求值，共享求解器未修改；0–7阶导数、结点、标量与批量查询均与原求值器回归对照。
开发时钟不再为了追赶墙钟而加速模型时间，否则75 ms规划可能错误跨过120 ms模型时间；所有实际周期超期仍原样统计。
数值实验不是独立物理、不是PX4/Gazebo。动作、最终状态与源码快照从冻结复测保存，可用于后续复核。

## 已发现的末段评分问题与复测

旧自主代价在最后一门完成后才开始累计终点距离平方，导致较早完成者多承担返航积分，存在推迟最后一次穿越的动机。
终点距离进展已有逐步差分项，不再重复加入分支相关的绝对距离代价；终端仅加速度平方/(2·最大加速度)的制动距离。
第一组三种子冻结复测为0/3完整任务成功；v2三次全部过七门，但仅1/3完成返航。
最新v3增加条件穿越期限和模型一致反馈，独立冻结复测3/3完整完成，源码哈希一致；所有失败保留。
一次完整成功为`gpu_passage_shooting_20260920_07`的42.86秒；2.5秒开发`_09`为42.70秒。
二者均只是同模型开发成功，不代表当前冻结复测全部成功，更不是Gazebo成绩。
最新开发`_10`完成43.70秒，但并行单门测试初始化期间出现225.75 ms单次超限，不能剔除后宣称满足预算。
正式复测不并行运行其他GPU任务。单门掉头测试从原8秒停滞改善为2.08秒完整退出，仅作为机制诊断。

## 后续PX4诊断与当前版本边界

真实PX4/Gazebo试飞没有复现上面的3/3。所有输出在`results/gpu_passage_px4_20260920_*`：

| 02 | 0 | 20.384 | 同上 | 无 |
| 03 | 1 | 29.796 | 同上 | 无 |
| 04 | 5 | 60.024 | 原60秒协议超时 | 无 |
| 05_extended | 2 | 31.104 | 缓存失效；未到90秒延长上限 | 无 |

所有结果均未成功，不能称0碰撞安全竞速。真值审计最小采样整机袖套净空分别
0.470431、2.364500、0.481871、0.449076、0.478960 m，工作区检查通过；这是采样审计，非连续安全证明。
04控制计算最大50.530 ms，含初始TOGT最大76.459 ms，0次>100 ms；无40 ms接入超时（已改60 ms）。
04平均速度3.33 m/s、最高7.96 m/s，尚不满足用户的快速全窗目标。

已确认并修正的接口问题：

- 未来控制的切换移到独立200 Hz发送线程，不等待主计算结束。02实测切换延迟中位0、最大8 ms。
- TOGT请求前重新获取当前反馈/时钟，避免把一次MPPI计算前的旧PVAJ当当前状态，提前消耗100 ms预算。
  01的TOGT接入39/321；02为170/171。但接入改善没有自动带来整圈成功。
- 区分旧移位方案远端不合格和近期危险。参考有风险或当前执行近100 ms有危险才直接自主；
  否则先尝试完整硬筛的跟踪候选，无合格候选再自主求解，两轮耗时全部计入。
- 两轮控制可能40–46 ms，原40 ms接入点使03的124轮迟到；固定改60 ms并完整预测这段已排队控制。
  这不是把TOGT头推进60 ms：TOGT仍由当前实际PVAJ启动。

当前源码包含以上接口/模式修订，v3的3/3不能直接归给当前源码；v4独立三种子回归结果如下。
尝试过带反馈加速度噪声的16384候选分布，`gpu_feedback_proposals_20260920_s0`仅5门/60秒超时，
中位27.02、最大58.72 ms；尚无性能优势，已从默认源码撤回。其完整源码与失败轨迹保留在该结果快照。
目前仍缺少实际闭环下的可行控制持续性，不能把它简单归咎于采样数量，也不能宣称递归安全。
